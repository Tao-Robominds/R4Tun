# Daily Journal — 22 February 2026

## Objective

Investigate GT coverage for regular agent preprocessing outputs (1-4, 2-2, 3-1) and test whether adding `double_zero_cutoff` and `smoothing_offset` parameters (as used in irregular/complex agents) can improve coverage to 100%.

---

## Context & Starting Point

| Metric | Value | Notes |
|--------|-------|-------|
| Regular agent coverage (1-4) | 98.16% | 939,598 / 957,258 GT-block points mapped |
| Regular agent coverage (2-2) | 97.79% | 1,213,284 / 1,240,703 GT-block points mapped |
| Regular agent coverage (3-1) | 99.71% | 2,234,636 / 2,241,034 GT-block points mapped |
| Irregular agent coverage | 100% | Uses `double_zero_cutoff=false, smoothing_offset=0.0` |

**Background:** The irregular/complex agents use GT-optimal denoising parameters (`double_zero_cutoff=false, smoothing_offset=0.0`) that achieve 100% GT-block coverage. The regular agent's preprocessing script hardcodes these values (`double_zero_cutoff` always ON, `smoothing_offset=-0.003`), potentially causing the 1-3% coverage gap.

| Configuration | Detection | Segmentation | mIoU | Notes |
|--------------|-----------|-------------|------|-------|
| **GT ceiling** | GT centres (all_segments_gt.csv) | GT-derived geometric | **0.599** | Absolute ceiling for geometric approach |
| **Offset ceiling** | GT K + GT offsets (Y-only, X from K) | GT-derived geometric | **0.525** | Per-block X variation costs -0.074 |

#### Gap Analysis

1. **Geometric approach gap** (0.599 vs ideal): Rectangular bounding boxes can't match irregular block shapes. A1 (0.477) and K (0.541) are weakest.
2. **X-position gap** (0.599 → 0.525, -12.3%): Per-block X variation (±110px) not captured by offset method which inherits K's X.
3. **Template expansion gap** (0.525 → 0.101, -80.8%): **The critical bottleneck.** Template rotation can't match the complex stagger pattern where block order changes between rings. CV up to 0.545 for inter-block steps.
4. **K detection gap** (0.101 → 0.094, -6.9%): K Y-positions off by 0-1800px for some rings, but this is minor compared to template failure.

#### Key Findings

1. **Template expansion is fundamentally unsuitable for complex staggered tunnels.** The stagger pattern rotates the block ordering so aggressively that a single template (even with rotation scoring) can't capture the variation.
2. **Per-ring offset method (42D) works but is too high-dimensional for BO.** With GT offsets, the Y-positions match exactly, but BO can't efficiently search 42 parameters.
3. **The geometric approach ceiling (0.599) is modest** — rectangular bounding boxes lose ~40% of potential mIoU even with perfect positions.
4. **Next priority:** Need a better GT-free expansion method — possibly groove-guided boundary detection, or a hierarchical BO that first tunes per-block-type offsets (6D) then refines per-ring (42D).

### Gap Analysis

- **GT ceiling → Non-GT:** 0.7995 → 0.171/0.177 = **78% mIoU drop**
- **Primary bottleneck: K Y detection.** The banded intersection method gives K Y values ~100-200px off from GT. With 12D grouped offsets applied to noisy K Y, all non-K positions are shifted proportionally.
- **SAM vs Geometric:** SAM slightly outperforms geometric (0.177 vs 0.171), but the gap is marginal. Both approaches are equally handicapped by noisy detection input.
- **A2 = 0.000 (geometric):** Block A2 is near the wrap boundary and its centroid lands in the wrong region. SAM partially recovers this (0.094).
- **All ~74 parameters are now BO-tunable** with no GT code remaining in the pipeline.
