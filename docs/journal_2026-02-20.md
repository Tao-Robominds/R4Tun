## Experiments & Results (chronological)

### 1. Reverse-engineering preprocessing: pixel_to_point coverage

**Idea:** With GT we can find why 337k points are unmapped and fix it. All unmapped GT points have `pred=0`; denoising removes them in two ways: (1) radius filter — 163k BG with r &lt; radius_min; (2) gradient surface cutoff — 197k (94.5k BG + 102.5k blocks).

**Fix (data-level):** Computed pixel coordinates for all pred=0 points using the same projection as `generate_depth_map`, appended them to `pixel_to_point.pkl`. No re-run of preprocessing. Original backed up to `pixel_to_point_original.pkl`.

**Result:** GT coverage 77.6% → 100%. Theoretical ceiling 0.884 → **1.000**.

### 2. SAM with GT centres (all_segments_gt.csv)

**Idea:** Use perfect detection input to isolate SAM’s ability to fix rectangle misplacement (BG inside blocks, overlap at boundaries). Rectangles misplace points; SAM should draw tight, image-driven boundaries and “regulate” them.

**Setup:** Swapped `all_segments.csv` to `all_segments_gt.csv` so SAM gets GT centres. Run SAM, evaluate mIoU.

**Result:** With **old SAM params**, mIoU 0.424. SAM masks too small; many points left as pred=0 (446k pred=7 → pred=0). With **GT-derived mask params (naive)** — max half-width/half-height per block type from GT pixel extents + margin — mIoU **0.072**. Masks/crops became full-image scale; SAM labels everything as block, BG IoU = 0. Over-segmentation.

### 3. Reverse-engineering SAM parameters from GT

**Idea:** Any parameter or fixed value can be derived from ground truth and made BO-available (rule in `.cursorrules`). Compute per-(block, ring) pixel extents from GT + `pixel_to_point.pkl`; ring mapping GT 107–113 ↔ all_segments 0–6.

**Finding:** Some blocks **wrap around** the depth map (theta periodic): pixel Y span reaches ~4700 px (full image height 4712). Naive “max over all rings” for mask height uses that wrap span → template mask full-image-sized → SAM segments whole crop → 0.072 mIoU.

**Saved:** GT-optimal (naive) params to `complex_agents/3_segmentation/parameters/5-1/parameters_sam.json`. Need wrap-aware extent (template = physical block size; crop may be larger for wrap) before re-running.

## Key Insights

1. **Wrap-around is hard.** Depth map vertical axis is theta (periodic). A block can span the boundary so its pixels lie in two bands (top and bottom). Pixel “height” of such a block is then ~full image height (e.g. 4700 px), not the physical block extent. If we set template mask height from “max pixel span” we get full-image-sized masks → SAM segments the whole crop → everything becomes block (BG wiped). Template mask should match **physical** block size; crop may need to be larger for wrap. Current code uses the same scale for crop and template; we need wrap-aware extent (e.g. detect wrap, use complement when span &gt; 60% of image height) or per-segment mask sizing.

2. **Preprocessing still needs to change.** The 337k fix was retroactive (data only). Preprocessing code still excludes pred=0 before projection. For a clean, reproducible pipeline: either relax denoising (e.g. lower `radius_min` from GT min-r, raise `gradient_threshold`) or change enhancing so pred=0 points are still projected into `pixel_to_point.pkl`. Until then, new tunnels or re-runs will have the coverage gap unless we re-apply the retroactive script or change the code.

3. **Why we skip detection for now.** We have `all_segments_gt.csv` (GT centres). Using it removes detection error and isolates: (1) preprocessing coverage (done), (2) SAM’s ability to replace rectangles with good boundaries. Closing the gap between detection output and GT centres (offset BO, drift 948→317 px) is deferred until SAM is unstuck and we have a solid segmentation baseline with perfect centres.

4. **What SAM is stuck on.** (a) Template mask vs crop vs wrap: mask must match physical block size; crop may need to be larger for wrap. Naive GT-derived pass used max pixel extent (including wrap) → template full-image scale → 0.072. (b) No clean separation in code for “crop size” vs “template mask size” when blocks wrap; both use K_height/AB_height and mask params. Next: wrap-aware extent computation, re-derive SAM params, re-run; optionally expose as BO search bounds.

5. **Reverse engineering from GT is now a project rule.** Documented in `.cursorrules`. For any parameter or fixed value, compute the correct value from ground truth first; use as reference or BO range.

## Reflection

Today we fixed the preprocessing ceiling for 5-1 by retroactively adding 337k pred=0 points to `pixel_to_point.pkl`, so the theoretical SAM ceiling is now 1.0. We then ran SAM with GT centres to see how well it can “regulate” rectangle misplacement. The main lesson is that **wrap-around** makes GT reverse-engineering for SAM non-trivial: we must use physical block size for the template mask and handle wrap separately for crop/aggregation. We also codified the rule that any parameter or fixed value can be reverse-engineered from GT and made BO-available. Detection is intentionally skipped for now so we can get SAM unstuck first; then we can close the detection gap and re-measure end-to-end mIoU.
