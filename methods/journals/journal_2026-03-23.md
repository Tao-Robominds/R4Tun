### 3. Characteristics path centralisation (`sam4tun/plugins/paths.py`)

- **`tunnel_id == "sample"`** → `data/sample/characteristics/` (universal reference for analysts).
- **Other tunnels** → `data/ablation/{ABLATION_TUNNEL_SUBROOT}/{tunnel_id}/characteristics/` with **`ABLATION_TUNNEL_SUBROOT = "memory"`** (single knob for future layout experiments).
- **Pipeline CSVs** unchanged: `data/{tunnel_id}/` (e.g. `unwrapped.csv`, `denoised.csv`, …).

**Wiring:** Plugins `1–4` + `raw_characteristics.py` write via `tunnel_characteristics_parent_dir` / `tunnel_characteristics_dir`; **agents** analysts use `Path(tunnel_characteristics_dir(tunnel_id)) / "*.json"` for tunnel side and **`data/sample/characteristics/`** for sample reference; **coders / reflecting** import the same helpers; **`run_agents.sh`** checks raw JSON path (sample vs `ablation/memory/...`).

## Key Insights

1. **One evaluation script with explicit schema** avoids duplicated 400-line files and wrong B2 vs A4 naming for tunnel 4/5.
2. **Sample characteristics live under `data/sample/characteristics/`** so they are tunnel-agnostic “memory”; subset study copies sit under **`data/ablation/memory/...`** and can be relocated by changing one constant.
3. **Class 8** is a pipeline sentinel for enhanced/synthetic points; high filter rates in mIoU runs usually mean many preds are still 8, not a schema bug.
4. **Plugin CLIs** need **`PYTHONPATH=.`** when invoked as files under `sam4tun/plugins/` (package import).
