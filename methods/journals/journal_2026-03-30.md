# Daily Journal — 30 March 2026

## Objective

Run the **memory+state** ablation condition across all 30 tunnels, iteratively tuning the LLM-driven parameter inference pipeline (orchestrator, CoT instructions, characteriser outputs, data subsets) until depth maps and mIoU are satisfactory.

---

## What "memory+state" adds over "memory"

| Aspect | memory | memory+state |
|---|---|---|
| LLM sees raw characteristics | Yes | Yes |
| LLM sees stage-by-stage characteristics | No | Yes (cumulative from all prior stages) |
| Parameter inference | Pre-computed offline | Live: LLM called per-stage, output feeds next stage |
| CoT in prompt | No | Yes (stages 1–5) |
| Orchestrator | `run_agents.sh` (static) | `run_memory_state.py` (interleaved LLM + pipeline) |

## Experiments

### 1. Orchestrator development (`run_memory_state.py`)

Built a Python orchestrator that, for each tunnel, runs a tight loop: for each of the 5 stages, (a) deletes stale parameter JSON, (b) dynamically imports the stage analyst to build an LLM prompt including cumulative characteristics, (c) calls Claude Opus 4.6, (d) extracts the JSON response, (e) runs the configurable stage script, (f) runs the characteriser plugin.

Key design decisions:
- **Stale parameter cleanup**: before each stage, the previously inferred parameter file is deleted so the LLM starts from the sam4tun baseline rather than anchoring to its own prior (potentially wrong) inference.
- **Raw characteriser pre-run**: always regenerates `raw_characteristics.json` before unfolding to use RANSAC-based diameter estimation.
- **Stage filtering**: `--stages` flag allows partial pipeline runs (e.g. first 3 stages only) for iterative tuning.

## Key insights

1. **State (cumulative characteristics) is the dominant driver of improvement.** Memory alone (raw characteristics only) actually hurt regular tunnels (-0.062 mIoU) while memory+state lifted them by +0.232. The LLM needs to see intermediate pipeline outputs to make informed parameter decisions.
2. **CoT "proven defaults" must explicitly override reference parameters.** Without the "CRITICAL" override section, the LLM anchored to sam4tun baseline values in the prompt's JSON block, ignoring textual guidance for better values.
3. **Quantile-based mask guidance (r_percentiles) is essential.** Providing p10–p99 of the radial distribution lets the LLM set `mask_r_low`/`mask_r_high` precisely per-tunnel instead of guessing from diameter alone. This eliminated the #1 cause of depth map white spaces.
4. **Subset quality matters more than parameter tuning.** All three continuous tunnels (3-1-x) had boundary or sparse ring subsets that no parameter adaptation could fix. Rebuilding subsets from full data with middle contiguous rings was the single largest quality improvement.
5. **Stale parameter cleanup prevents LLM self-reinforcement.** Without deleting the prior inference before each stage, the LLM sees its own (possibly wrong) previous output and anchors to it, compounding errors across stages.
